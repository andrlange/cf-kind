# cf-kind-demo — Implementation Roadmap

**Spec:** `CLAUDE.md` (chapter numbers below refer to it). Each phase gets its own detailed plan in
`docs/superpowers/plans/`, only once the previous phase has been accepted. Each phase ends with working, testable software.

| Phase | Content | Chapter | Result / acceptance | Plan |
|---|---|---|---|---|
| **0** | **Prerequisites**: Brewfile, `make prereqs`, `config.env` + `make configure` (domain/TLS pre-task), local DNS (`make dns`), GCP DNS key in the Keychain (`make secrets-set-dns`), test harness (bats, shellcheck) | 3, 9.2, 10, 13 | `make prereqs` green on this Mac, `make config-show` shows derived domains, `dscacheutil` resolves `api.<SYSTEM_DOMAIN>` → 127.0.0.1, `make test` green | `2026-09-22-phase0-prereqs.md` |
| 1 | **Upstream + provider `kind`** (reference): pinned upstream checkout, provider adapter interface, `make up/down/login/bootstrap/status` with `127-0-0-1.nip.io` self-signed | 2, 4.2, 4.4, 11, 12 | `cf push hello-js` runs, `make down` cleans up completely | to follow |
| **L** | **Language: English** — translate CLAUDE.md, README, plans, comments, config descriptions, log messages, test names | Header of CLAUDE.md | no German text left in the repo (check: `make lint-language`), all tests green | to follow (after phase 4) |
| 2 | **Provider `docker-desktop`**: enable Kubernetes via settings patch, cell labels/taints, `CNI=none` patch, gateway as LoadBalancer, mirrors via `docker exec`, `repair` after restart | 4.1 | as phase 1, but on Docker Desktop K8s; feature gaps in `docs/providers.md` | to follow |
| 3 | **Domain & TLS**: patch `domain-and-tls` (split/flat), `make certs` (lego + GCP Cloud DNS, staging→prod), `public-tls` secret, `make dns-public`, `certs-autorenew` (launchd), `trust-ca` (mkcert) | 9 | `cf login -a https://api.<SYSTEM_DOMAIN>` without `--skip-ssl-validation`, renewal test run | to follow |
| 4 | **Network robustness**: fixed Docker subnet, static node IPs (kind), `make doctor`/`repair`, time drift check, acceptance test | 10 | test plan Wi-Fi change/offline/Docker restart/sleep documented green per provider | to follow |
| 5 | **Airgap**: Artifact Keeper + Garage as Compose stack, `airgap-fill/verify/export/import`, mirrors to AK, mirror buildpack dependencies | 6 | `make nuke && make up && make demo` without internet | to follow |
| 6 | **Service automation**: port an existing Go broker (brokerapi v13) from a prior reference implementation, operators (CNPG + pgvector, mariadb-operator, valkey, RabbitMQ + Topology), `make services`/`services-test` | 7 | all 4 services: create → bind → app uses VCAP_SERVICES → unbind → delete | to follow |
| 7 | **Developer experience**: Stratos spike (darwin-arm64 binary, UAA client), custom Apps Manager clone if needed, demo apps, `make demo`, demo script | 8 | guided 10-minute demo runs through | to follow |
| 8 | **arm64-native buildpack dependencies** (node, openjdk, go, nginx, python), repack of the buildpacks, NFS image replacement | 5 | demo runs with Rosetta disabled | to follow |
| 9 | **Provider `k3d`** (optional) | 4.3 | as phase 1 on k3d | to follow |

Rationale for the order: phase 1 before 2, because `kind` is the upstream reference and errors in phase 2 would otherwise not be
distinguishable from upstream errors. TLS (3) before airgap (5), because the domain feeds into all mirror/hostname decisions.
